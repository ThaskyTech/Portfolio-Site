Civic Connect

A community service-request platform, built over four milestones for my software engineering module (SEN381), which teaches engineering a system end to end.

STATUSDelivered, October 2026
TEAMThree students
MY ROLEGitHub lead, backend security
STACKASP.NET Core, Angular, PostgreSQL (Supabase)

The problem

Community organisations often handle requests such as facility faults, IT support and lost property through a mix of email, phone calls and paper. Staff struggle to prioritise, requesters can't see the status of their request, and reporting is hard to audit. Civic Connect replaces that with one controlled, traceable system.

What we built

  • Requesters submit requests, track status and history, and get email updates.
  • Staff search their queue, accept or reject assignments and move requests through controlled status steps.
  • Admins assign work, manage categories and use a dashboard backed by an append-only audit history.
  • Architecture: a layered modular monolith: one ASP.NET Core API with Request, Auth and Notification modules, an Angular client and a relational PostgreSQL database.
  • Security: JWT authentication, bcrypt hashing and role-based access control enforced on the server.

How we engineered it

  • Decisions on record: ADRs for a table-driven status-transition validator and a dependency-injected notifier, plus a documented stack and database comparison.
  • Change control: five approved change requests, each with an impact analysis.
  • Testing: 58 unit tests, 64 integration tests against PostgreSQL, 31 Angular spec files and a Cypress smoke test, traced to requirements.
  • CI quality gate: every pull request is built, tested, linted, audited and secret-scanned, with two peer reviews before merge.

My part

I owned the GitHub side: the branching strategy, the CI checks and pipelines, and pull request review. I also implemented the security features, including role-based access control, and defined the project's tests.

What I took from it

Settle the role model and the frontend and backend contract early, update documents in the same pull request as the code, and plan deployment from the start.
